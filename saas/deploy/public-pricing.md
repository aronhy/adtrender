# 正式套餐发布与撤回

官网价格、登录后的可购套餐和新购买请求使用同一可售条件。`ACTIVE` 只表示套餐已启用；测试套餐、旧记录以及未经公开确认的版本不会自动成为正式报价。

## 默认状态

- `PUBLIC_PRICING_ENABLED=false`，官网显示待公布，不读取开发默认试用数字。
- 第七次迁移只向 `PlanVersion` 增加可空的 `verifiedProviderMode`、`publicConfirmedAt`；历史记录保持未确认，既有价格、额度和订阅不变。
- 测试支付仍可单独演练。测试模式不会出售已核验为 LIVE 的版本，也不会把测试价格展示到匿名官网。

## 操作顺序

先由业务确认币种、月价、四类额度和退款规则，并在 Stripe 中准备对应的正式月付价格。使用指定服务器的私有环境文件注入凭据；不要把凭据放进套餐 JSON、命令参数或仓库。

1. 使用原有 `plan-import` 导入明确的版本，`mode=live`。命令只读取 Stripe 价格核对金额、币种和周期，记录为 `DRAFT`，不修改旧版本或现有订阅。
2. 使用 `plan-activate` 启用该版本。正式启用需要 `LIVE_BILLING_ENABLED=true`，但此时仍未公开。
3. 使用独立的 `plan-publish` 确认该版本可以公开报价。命令重新读取 Stripe 价格并记录审计；只有当前有效的平台管理员可执行。
4. 核对完整正式支付配置后，设置 `PUBLIC_PRICING_ENABLED=true`，按当前部署方式更新 API/worker 配置。该开关同时要求 `BILLING_ENABLED=true`、`LIVE_BILLING_ENABLED=true`、正式服务端密钥、Webhook 密钥和显式退款规则。配置不完整会拒绝启动或返回服务未就绪。

命令在对应版本代码目录运行，使用已存在的平台管理员邮箱和业务确认的版本，不自动创建管理员：

```bash
saas/scripts/admin.sh plan-import --actor-email '<平台管理员邮箱>' --file '<绝对路径/经确认套餐.json>'
saas/scripts/admin.sh plan-activate --actor-email '<平台管理员邮箱>' --key '<套餐key>' --version '<版本整数>'
saas/scripts/admin.sh plan-publish --actor-email '<平台管理员邮箱>' --key '<套餐key>' --version '<版本整数>'
saas/scripts/admin.sh plan-unpublish --actor-email '<平台管理员邮箱>' --key '<套餐key>' --version '<版本整数>'
```

在镜像中维护时，应使用该版本包含的管理员命令及隔离测试库连接；本页不授权自动发布任何业务价格。发布新版本不会隐式撤回旧版本；需要替换报价时，明确撤回旧版本。匿名目录最多展示 100 个已确认版本，超限拒绝返回，避免静默截断。

## 客户流程

官网仅返回名称、套餐版本 ID、价格、周期和四项额度。选择套餐后，邮箱或 Google 登录可继续进入设置页；首次创建团队后仍保留选择。用户选择组织，服务器重新核对所有者身份、套餐可售状态和 Stripe 价格后才能创建结账或预约变更。页面参数不能授权购买。

试用的公开时长和数字仍待业务确认；当前版本只展示已开通的实际试用权益，不发布开发默认值。

## 撤回的范围

`plan-unpublish` 移除公开确认并记录审计；官网和新的购买/变更请求不再提供该版本。撤回与新结账共用目录锁，避免核验后再创建请求的竞态。

撤回不删除套餐，不改变历史订阅、已付权益、续订对账或取消流程，也不自动取消此前已经创建的 Stripe Checkout 会话。若需处理已有支付会话，必须在供应商侧单独核对。关闭公开总开关同样不代表退款、删除或停止已有订阅。

本轮只在本机使用明确标记的合成价格和模拟供应商验收；测试服务器保持公开价格及真实收款关闭。
